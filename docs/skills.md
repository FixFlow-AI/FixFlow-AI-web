# FixFlow AI - Core Subsystems & Skills Manual

This document details the design principles, operational guidelines, and code mappings for the five core engineering subsystems ("Skills") injected into the **FixFlow AI** codebase.

---

## ⚙️ Core Subsystem Catalog

### 1. Enterprise Semantic Brief Parsing & Schema Enforcement
*   **Purpose**: Processes highly chaotic, unstructured client inputs (text briefs, PDFs, chats) and maps them into deterministic JSON structures for proposal pipelines.
*   **Key Design Patterns**:
    *   **Strict Zod Guardrail**: Incoming JSON inputs are parsed using strict schema validation (`BriefOutputSchema`) which rejects unknown properties or malformed types.
    *   **Native Gemini Schema Injection**: Restricts Gemini's model output to a valid structured format utilizing native JSON schema constraints (`responseJsonSchema`).
    *   **Fallback Heuristics**: If schema parsing fails or throws an exception, the system automatically routes the payload through a sanitization function (`sanitizeAndPatchBrief`) that fills in missing properties with default safe strings or arrays, ensuring zero app crashes.
*   **Code Implementation**: [briefParser.ts](file:///c:/Users/suvam/Desktop/VS%20code/Projects/FixFlowAI/backend/src/skills/briefParser.ts)

### 2. Deterministic Multi-Agent Orchestration (The Confidence Grid)
*   **Purpose**: Validates generated proposals against the original source brief using parallel persona workers, avoiding raw non-deterministic LLM evaluation loops.
*   **Key Design Patterns**:
    *   **Persona Isolation**: Runs parallel Gemini API requests for two distinct agent personas:
        *   *Auditor Agent*: Evaluates deliverables and flags budget alignment.
        *   *Feasibility Agent*: Checks technological feasibility and validates the realistic nature of timelines.
    *   **Mathematical Consensus**: Computes the mean of the scores from both agent evaluations to generate a 0-100 Confidence Index.
    *   **Idempotency & Resilience**: Treats evaluation results as immutable states that are logged and tracked in the database rather than running as transient memory.
*   **Code Implementation**: [confidenceGrid.ts](file:///c:/Users/suvam/Desktop/VS%20code/Projects/FixFlowAI/backend/src/skills/confidenceGrid.ts)

### 3. Secure Milestone Mechanics & Versioning
*   **Purpose**: Manages the secure, transaction-safe lifecycle of milestone payments, deposits, and client-freelancer escrow releases.
*   **Key Design Patterns**:
    *   **Finite State Machine (FSM)**: Restricts milestone tracking to valid state transitions (`[Draft, Pending_Deposit, Active, In_Review, Revision_Requested, Approved, Funds_Released, Dispute]`).
    *   **Cryptographic Audit Trails**: Each state change generates a SHA-256 block-like hash chained to the `previousHash`, recording the timestamp, triggering user ID, role, and the state difference.
    *   **Optimistic Concurrency Control**: Uses an integer `version` field on the milestone records. If two operations attempt to update the state concurrently, the database rejects the second one because of a version mismatch, preventing double-payment releases.
*   **Code Implementation**: [escrowStateMachine.ts](file:///c:/Users/suvam/Desktop/VS%20code/Projects/FixFlowAI/backend/src/skills/escrowStateMachine.ts)

### 4. Cloud Infrastructure Scale & Pipeline Optimization
*   **Purpose**: Provides high-throughput real-time collaboration between agency and client dashboards without stalling the Node.js event loop.
*   **Key Design Patterns**:
    *   **WebSocket Stream Multiplexing**: Rooms are allocated per proposal. WS frames route subscribing clients and broadcast mutations.
    *   **Causal Vector Clocks**: Clients and servers track changes using vector clock maps (`Record<string, number>`) to trace logical edits.
    *   **Last-Write-Wins (LWW) Fallback**: For concurrent updates on identical fields, client timestamps act as the final conflict resolution tie-breaker.
*   **Code Implementation**:

### 5. Pinpoint Self-Correction & Root-Cause Diagnostics
*   **Purpose**: Automates error correction when LLM structured outputs fall below quality benchmarks.
*   **Key Design Patterns**:
    *   **Self-Correction Loop**: If the Confidence Index generated by the *Confidence Grid* falls below `75`, the system triggers an autonomous optimization routine.
    *   **GAP Feedback Prompting**: The system extracts the explicit issues list compiled by the Auditor and Feasibility agents and feeds them back into a specialized optimization prompt alongside the original brief and proposal.
    *   **Automatic Proposal Reconciliation**: The optimization agent regenerates the proposal correcting the flagged issues, saving round-trips and manual editing time.
*   **Code Implementation**: [confidenceGrid.ts](file:///c:/Users/suvam/Desktop/VS%20code/Projects/FixFlowAI/backend/src/skills/confidenceGrid.ts#L104) (see `optimizeProposal` function)
